## 一、应当能推翻优势的检查

| 质询 | 最有杀伤力的检验 | 不通过时必须怎样改结论 |
|---|---|---|
| MILP只是击败弱FIFO？ | 和允许交换/重新插入/多起点搜索的强基线比较，报告同等预算 | 持平则不声称普遍成本优势；解释何种情景需要全局求解 |
| 箱龄特意靠近费用跳档？ | 积压、年轻箱、分批到港、集中释放等预固定机制分别报告 | 只在一种机制有效则限定该机制，不报无依据企业平均 |
| 24例其实只4组数据？ | 比较完整订单内容哈希；记录种子共享、规模前缀重用、容量重复 | 报独立订单组数；不按case数计算独立样本置信度 |
| 减去期前费用放大百分比？ | 同一配对集合重算绝对KRW差、增量分母、总额分母 | 同屏双分母；不得使用“已支付费用”标签 |
| 失败订单被删掉？ | 原输入箱号与完整结果一一对应；失败成本必须null | 删除其费用比较资格，但保留失败数；禁止将部分费用当0 |
| 适用合同解释一变就不优？ | 免费期/费率/收费模式改变并交叉评价原方案 | 声明默认假设条件性，不称合同已验证或普遍稳健 |
| 联合费用只是换个名称？ | PNC-only、D&D-only、joint方案统一按目标费用复算 | 无差异则不能声称联合目标带来性能改善 |
| 模型利用了日级漏洞？ | 同日/次日返空、箱/TEU、日内释放、末端全清空敏感性 | 只称指定日级抽象内可行，不说现场可执行 |
| “实时”用到了未来？ | 逐步检查当时信息集；所有方法同样处理扰动 | 全知结果单列作参考，不归入在线可实现改善 |
| “最优”掩盖超时？ | 状态、可行解、界/间隙、墙钟与求解器预算分开 | 未证明者称可行候选；没有解不等于证明无解 |

## 二、V1已确认事实与V2不得复用的结论

- V1的23对场景增量下降9.812916%，总费用下降4.588633%；算术成立，但仅相对当时三种贪心实现。
- V1每个seed的8箱是16箱的前8箱，三种容量复用订单；24case不是24个独立订单集。
- PNC与Maersk两项相加在保存的Maersk通知中有依据，不能仅凭Combined名称认定双计；具体合同适用性仍缺失。
- 2026 PNC正式PDF有生效日期和追溯算例；旧网页冲突已披露。
- Maersk逐档累加、实际合同、日级现场可行性及真实企业价值仍属独立证据缺口。
- 联合拆箱/提还箱与D&D已有直接先例，不能因实现本地原型就宣称首创。

## 三、数值复算协议

对每个case按实际输入收集所有指定baseline结果，独立检查完整性与可行状态，再选最小完整可行基准。候选优化方法的定义必须固定，不能每个case从额外方法里挑赢家却继续称同一算法。候选若是“求解器+回退启发式”，明确报告复合策略与总预算。

独立加总配对case的基准/候选费用，保留负差，报告`paired N`、基准无完整解、候选无完整解、零分母、正/零/负改善数。核对文件summary与逐case结果。按机制、规模和容量分层；不能把替代合同压力测试混入默认业务收益总数。

同一case内`totalCost−incrementalCost`应为所有策略共同的基数；各项费用相加一致。所有成功结果应包含全部箱且无重复；抽查费用边界、容量、期限并复算实际失败案例。独立复算代码不应直接调用被审核汇总函数。

预算报告须区分：首次模块/求解器加载、模型构建、求解器内部时限、后处理与审计、端到端墙钟。固定迭代基线与固定秒数优化器不自动构成严格等预算实验，应披露差别并避免夸大效率结论。

## 四、证据门槛，而非虚构评分

- **可公开演示研究原型：** 数字、来源、完整性与状态一致；弱点在相关结论旁披露；源码和结果可定位。
- **可主张相对强基线的情景改善：** 同信息、同约束、预算解释清楚；失败/持平/负改善全部公开；变化不依赖遗漏病例。
- **可主张某机制贡献：** 对应消融表明差异，且统一收费复算无偏置；反例也报告。
- **可主张指定范围的稳健性：** 预先固定扰动集合与信息规则，逐组结果完整；未测试范围不扩张。
- **可主张现场价值：** 必须有实际订单与业务合同/资源核验；当前公开来源不能代替。

任何门槛未达到，都收窄相应声明，不用加权自评分掩盖关键缺证。

### 消融：排程变化不是费用贡献，未完成平局优化也不是严格证据

8个敏感性基础订单中2个模型不可行，全部7变体都保留。6个可行基础订单用于默认计费复评。

| 变体 | 默认joint收费复评的额外费用 | 支持范围 |
|---|---:|---|
| PNC误设逐档累加代理 | 185,200 KRW，默认总费用的2.2178%（6对） | 支持这批订单中正确追溯机制可能影响决策；不证明普遍增益 |
| D&D最高档重计压力解释 | 97,650 KRW，1.1694%（6对） | 表示解释风险，不证明任一解释为真实合同 |
| 免费期扩展并移动全部档位 | 1,162,700 KRW，13.9236%（6对） | 是刻意合同假设错配复评；真实加购免费期不一定移动档位 |
| storageOnly，所有观测方案 | 189,350 KRW，2.2675%（6对） | **不能整体作为严格联合目标贡献**：其中101,800来自未完成次级优化的base8 |

`storageOnly`必须先证明仓储目标最优，再固定该最优值最小化joint费用。`sensitivity-base-8--storageOnly`的`tieBreakStatus=no_secondary_incumbent`，因此原排程可能只是忽略D&D时选到了任意差平局。其101,800不能伪装成联合目标不可避免的优势。红队指出后汇总新增严格子集，原数据没有删掉或重跑。这是本轮实际修正的一项重要结论边界。

“37.5%箱的日期改变”等比例本身不是价值证据：零费用case也可以因大量等价最优解改变日期。所有机制结论同时看费用与状态。

### 运营压力与保守缓冲：有成本的有限范围保证

`data/robustness-v2.json`使用6基础订单、4作业假设和3固定扰动。原静态计划18次扰动检查有16次失效。18次事后全信息重算都可行，但没有冻结已执行动作，不能叫线上恢复成功。

观察到这16次失效后另做`data/conservative-v2.json`：给**所有箱**预留1天额外卸货、**全周期每日**保留2次运输额度；不偷看具体故障箱或日期。该实验是事后设计的探索性补充，与主48case分开，不是独立确认性证明。6计划都完整可行，18次指定扰动检查0失效；6组基础订单仍反复使用，不能估计随机失效率。

独立复算原总两费14,408,650→保守19,061,200 KRW，增加4,652,550 KRW，**32.28998%**；增量费用口径为76.88196%。3个新到港case成本仍为0；3个积压case额外费约30.22%–35.16%。因此“免费获得韧性”是错误结论。

可以给出一个窄但明确的数学保证：固定提/卸开始/还箱日期，实际卸货天数介于名义与名义+1天、每一天运输额度不低于max(0,名义−2)、其他输入不变时，任何范围内实际占用都不大于保守计划校验的最坏占用，所以该固定计划满足所述日级约束。这是集合包含/单调性保证，不依赖把18次测试当作概率证据。它不覆盖放行推迟、超过1天的卸货延误、更大运力下降、仓库/场地削减、日内路径或预约限制。

## 六、目前能证成的贡献与剩余证据门槛

**能说：** 对指定韩国公开收费规则作了可核验实现；相同输入约束下，在主48组合成订单的36个可配对case中，相对本版有限强搜索候选有20,073,600 KRW费用下降；已定位正常新到港零收益、100箱求解失败、单目标消融的平局风险，以及付费缓冲可换取指定扰动集合内的模型可行性。

**不能说：** 优于现有先进调度算法、首次联合提还箱/拆箱/D&D、真实企业节省15.74%、100箱可靠解决、已实现在线滚动、现场韧性全面解决、官方允许英语/单人/AI、可预测获奖概率。

相关工作[`prior-art-v2.md`](prior-art-v2.md)已核实9项研究与3项产品。其中Jeong2020/2026有直接概念先例，PortPro已能自动匹配满箱提取与空箱归还预约；不得说竞品只显示费用。规则状态见[`rules-status-v2.md`](rules-status-v2.md)。

下一步最有价值的否证实验：

1. 在未使用种子上，给排列搜索与MILP同等端到端预算，并加入能直接调整事件日期的邻域，检验15.74%是否大幅消失；保留延时长尾和无解差异。
2. 固定保守缓冲规则，在未使用的订单机制与容量上检验额外成本/无保守可行解；主动测试范围外的释放延期、2天卸货延误、仓库/场地损失，显示保证失效边界。
3. 从开放论文数据/代码建立一个可兼容对照，同时保持费用与约束一致；若公开记录不足以组成完整PNC订单，继续称合成情景研究，不制造实单标签。

这些门槛衡量证据强度，不是官方打分或夺冠承诺。
