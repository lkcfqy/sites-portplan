## 30/36静态失败的具体回答

全部六条都在`aged-backlog + tight`。以下状态来自原始V5档案和独立native核验，不是新增实验：

| 主case末段 | fastEvent 1秒状态 | 独立native结论（另加验证预算） | 可说什么 |
|---|---|---|---|
| `tight-n16-r1` | 搜索未找到完整解 | 最优、完整可行 | 算法短预算未覆盖，不是数学无解 |
| `tight-n16-r2` | 搜索未找到完整解 | 证明不可行 | 此固定输入的硬约束冲突，增加搜索时间不保证能解决 |
| `tight-n50-r1` | 搜索未找到完整解 | 完整可行、有下界、未证最优 | 已有额外预算可行见证；不能称企业可执行或最优 |
| `tight-n50-r2` | 搜索未找到完整解 | 最优、完整可行 | 算法覆盖缺口 |
| `tight-n100-r1` | 搜索未找到完整解 | 完整可行、有下界、未证最优 | 规模与紧容量下的短预算缺口 |
| `tight-n100-r2` | 搜索未找到完整解 | 完整可行、有下界、未证最优 | 同上，必须保留失败 |

完整ID均以`v5-aged-backlog-`开头。原MILP对上述五个可行输入在1秒父预算内没有完整结果；额外native模型有解不能计作1秒方法成功。六个3秒控制复用主输入、按预声明运行，不能把控制结果并入30/36或宣称42个独立场景。

可直接说：“我们的启发式交付覆盖更高，但仍有5个模型可行输入在1秒内找不到解；另1个硬约束不可行。这是需要继续优化并解释的边界，不是都能落地的承诺。”

## 16/24滚动失败的具体回答

两策略八条失败全部`tight`，24条首日决策记录的比较均一致，其中3条day0双方都没有完整初始计划；不能把相同空记录当成已经有计划。失败都是`no_complete_plan`、底层`plannerStatus=infeasible`，但无解的**时点和模型范围**不同：

| case（完整前缀`v5-rolling-`） | 失败day（0起） | 解释范围 |
|---|---:|---|
| `aged-backlog-tight-n12-r1` | 0 | 初始名义硬约束已无解，尚未遇到未来冲击 |
| `aged-backlog-tight-n24-r1` | 0 | 同上 |
| `batch-release-tight-n12-r1` | 0 | 同上 |
| `aged-backlog-tight-n24-r2` | 3 | 当时资源观测＋固定执行历史＋期限/终点无延续 |
| `new-arrivals-tight-n12-r1` | 4 | 同上 |
| `aged-backlog-tight-n12-r2` | 5 | 同上 |
| `new-arrivals-tight-n24-r2` | 8 | 同上 |
| `batch-release-tight-n12-r2` | 8 | 同上 |

后三类限制不能通过把昨天的提箱改到另一日、暂停已开始的连日卸货、丢订单或把未完成费用标0“修复”。当前无解不等于事前全知模型无解，也不等于现实没有加车、换仓、协商期限等应急办法；这些办法当前没有成本、授权或动作模型。V6若加入诊断/干预必须另有协议和结果，本文件不提前宣称解决。

## 对接实单需要什么字段

这里是字段需求说明，不是要求现在联系企业，也不是把企业资料变为公开研究的完成前提。当前CSV能导入`id,sizeFt,dischargeDateTime,releaseDay,unloadDays,dueDay,dataOrigin`；资源、作业与收费设定来自scenario。最低可信实单接入应在**同一箱生命周期粒度**上具备以下字段。

| 数据层 | 所需字段 | 可得来源类型 / 当前缺口 | 不能用的替代 |
|---|---|---|---|
| 生命周期键 | 去标识进口行程ID；箱型；关联的船舶卸船、提箱、卸货、返空记录键 | 经合法授权的订单/TOS/WMS事件或带稳定键的公开链路；本项目未取得 | 遮罩车牌不是稳定箱号；同一实体箱多次航程不能直接拼成一条订单 |
| 收费时间 | 实际卸船时间及明确时区、提箱gate-out、约定场站空箱gate-in | 官方单箱事件/授权台账；08:00计费边界需要可靠分钟级卸船时刻 | 船期ETA或车辆闸口时刻不能代卸船时刻；缺失不补零 |
| 真实可提 | 海关放行、DO/港口release及其时刻，实际可提日 | 授权放行记录；转换到日模型须记录保守规则 | 把卸船日自动当可提日；使用后来知道的放行信息回填早先决策 |
| 仓库作业与期限 | 仓库/客户ID、开始/结束卸货、连续/可中断约定、真实货物交期 | WMS/收货日志、已确认订单；当前卸货天数和dueDay为模拟 | 光阳车辆场内时间不是客户仓库拆箱时间或公路时长 |
| 资源约束 | 每日运输作业额度、卸货槽和跨日箱位；实际容量变动的公告时刻、有效时刻和观测回执 | 经授权排班/设施资料；未来可用信息与事后实际值分开 | 车辆数直接等于箱次；缺记录日容量设0；事后冲击提前给在线策略 |
| 执行状态 | 实际已提/已开始卸货/已还空事件及回执时刻；不可逆状态 | 签收/作业日志；重复事件与改正事件有版本/来源 | 单纯把昨日计划当昨日真实完成；为可行而修改执行历史 |
| 合同收费 | 承运人/码头、合同版本及适用日期/PCD、单票免费期、收费档位/累计方式、付款人、税/发票行 | 单票合同或当前官方可核算依据；Maersk韩国跨档解释仍待确认 | 公开标准价覆盖所有合同；把2025网页与2026PDF冲突当已解决 |
| 对照策略 | 当时可知订单/容量的snapshot、实际采用计划、版本/发布时间、例外与取消记录 | 可审计计划台账；用于真实时间留出及同信息比较 | 只收最终漂亮计划；让优化策略提前看未来、让人工基准看不到当时信息 |

当前收费参数主要是场景级；同一批多承运人、不同单票免费期和合同规则需适配器或模型扩展，不能仅给CSV加一列便认定已支持。分钟时间转日约束会丢弃日内顺序；如要发出现场可执行派车单，还需道路/服务时间、预约窗口、司机与车辆可用性等路线层数据和验证。

只有公开光阳访问、仁川CODECO零散事件或未获取的派车目录时，继续保持公开组件验证与模拟实验，不补造合同、放行、仓库或账单。真实验证可以从一个已明确合同且字段齐全的小批次开始；金额复算、约束可行和实际节省是三个分开的验收问题。

三分钟韩文理解稿（练习用，不认定本人已经能讲；时长需实际试讲）：

> PortPlan은 정해진 수입 컨테이너를 언제 반출하고 적출한 뒤 공컨테이너를 반납할지 계획하는 공개자료 기반 연구 원형입니다. 사용자는 운송과 창고를 함께 조정하는 계획 담당자를 상정했습니다. 지금 보시는 주문과 장애는 생성 자료이며 기업 운영을 검증했다고 주장하지 않습니다.
>
> PNC 공개 요율은 도달한 최고 구간을 유료 일수 전체에 소급합니다. 20피트 상자가 14일 머무르면 318,500원, 15일이면 500,500원으로 182,000원이 추가됩니다. 이 숫자는 요율 계산 예시이고 최적화 절감액이 아닙니다. 반출과 반납이 운송을 공유하므로 개별 상자의 요금 순서만으로 전체 계획을 정할 수 없습니다.
>
> V5는 같은 합성 생성기에서 새로 고정한 36개 입력으로 세 정책을 비교했습니다. 초기화와 검산까지 포함한 1초 안에 빠른 구성과 날짜 탐색은 30개, 기존 날짜 탐색은 27개, 기본 MILP는 24개 완전 계획을 전달했습니다. 기존 탐색과 함께 완료한 27쌍의 추가요금 합은 4.06퍼센트 낮았지만 네 사례는 더 비쌌습니다. 기본 MILP의 완료 쌍보다도 더 비싸므로 보편적 최저비용이라고 하지 않습니다.
>
> 실행 중에는 오늘까지 알려진 용량과 실제 작업 이력만 받습니다. 이미 실행한 날짜를 고정하고 남은 계획이 여전히 유효하면 유지합니다. 두 정책 모두 24개 중 16개 경로를 완료했습니다. 함께 끝난 16쌍에서 날짜 변경은 621회에서 164회로 줄었고 총요금은 3,200원 늘었습니다. 변경 횟수는 실제 인건비가 아니며 유지 계획은 현재 최적이라고 보장하지 않습니다.
>
> 실패도 그대로 공개합니다. 정적 여섯 실패 중 하나는 모델이 불가능하고 다섯은 별도 native 검증에서 가능했습니다. 실행 실패는 시작부터 불가능한 경우와 이력을 고정한 뒤 계속할 수 없는 경우를 구분합니다. Python과 HiGHS의 독립 구현 및 별도 실행 장부로 비용과 제약을 확인했지만 외부 인증은 아닙니다. 코드, 원자료, 프로토콜과 AI 기여 기록을 제출자료로 제공합니다. 본인 검토와 당해 AI 참가 조건은 확인되지 않은 상태입니다.
