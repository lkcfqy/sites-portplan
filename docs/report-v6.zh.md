# PortPlan V6：失败证明与短预算完整执行的取舍

36个新种子合成场景中，带执行锁的构造与恢复完整执行 **29/36**，V5保留策略 **23/36**；100箱子组由 **5/12** 增至 **10/12**。这是相同生成机制内、冷进程完整episode统一5秒硬预算下的覆盖改善。共同完成的23条路径新增两费反而增加 **9,361,000 KRW（12.2562%）**，日期变动 **715→1,062**，没有同时改善费用和稳定性。

新增6个完成案例中，5个V5基准在D+0没有完整初始方案；另1个基准在D+3失败，但双方初始方案不同。差异结合初始构造和后续决策，不能称6次冲击后修复同一执行前缀，也不能单独归因于执行锁组件。

## 方法与前置协议

模型联合选择提箱、卸货起始、还空日，使用既有公开PNC仓储及Maersk Combined D&D研究计费函数，约束运输箱次、持续卸货槽和跨日箱位。全部订单在开始时已知，每日只揭示当前实际容量，未来冲击持续时间及实际容量不提供给决策器。运输箱次不是车辆数；没有道路路线、实时新增订单、预约和合同结算模型。

新策略保留审核有效的完整计划；失效时，严格保持已执行日期，用构造、有限回退和迁移产生完整候选，再在剩余预算内求解MILP。过去和未来的持续卸货及在场占用共同审核；不能重排已发生动作，没有当前最优保证。[恢复方法](recovery-method-v6.md)和[预测方法](persistence-method-v6.md)列出完整定义。

[协议](../data/protocol-v6.json)在读取新种子结果前冻结：种子81001–81036，三种机制、两档容量、24/50/100箱、各两次重复；4种固定两日容量冲击按索引分配。方法顺序轮换，每次一个冷进程，主留出先于开发控制。这是本地前瞻固定协议，未经外部注册。

父层从fork前计时，经冷加载、全部决策及最终引擎和独立费用/约束审核，到交付完整记录，统一硬预算5,000ms。旧V4/V5的每次0.2秒是求解器内部上限，新V6的每次200ms是包含构造、建模和审计的协作式预算，不能称相同每调用硬预算。绑定和审核可实际超出，原档保留全部墙钟；共同相等的是完整episode父层硬时钟。本轮没有硬截止或最终审核失败。

## 开发控制和旧失败的解释

另24个案例完全复用旧V5输入与扰动，只作为开发控制，不能扩充新留出分母。每日重算、V5保留和执行锁均16/24，一日预测12/24。执行锁与保留的16个配对费用完全相同，日期变化164→160，没有救回旧失败。一日预测损失4个原可完成例，12个配对新增费+2.1544%。

离线独立HiGHS诊断旧8个失败案例：3个名义模型起初不可行；4个名义可行、事后实际完整模型不可行；1个实际完整模型可行，但双方已执行前缀不可恢复。16个失败方法episode的当前观察加执行锁模型都被证明不可行，不能只凭旧0.2秒超时推断。额外离线预算不进入在线成绩，全知方案也不等于过去可实施方案。

旧24个案例有7个事后完整模型不可行，故旧组理论最多17/24；该界不能套到V6新组。新方法仍没有救回旧组唯一事后可行的失败例。[三层诊断](failure-diagnosis-v6.md)保留输入、模型、界、解和执行锁。

工作台新增必要条件解释：对日期区间累加每箱全部合法日期三元组的最小资源占用，若总需求下界超过可用容量即证明矛盾。独立Python标准库穷举核对40个输入、64,808个合法三元组、4,200个区间和15条发布见证。旧16条失败路径仅4条能由这些简单条件解释；其余12条未判定，绝不称可行。旧唯一事后可行失败例，在执行前缀下D+8–D+13运输至少需24箱次、容量22，这是累计缺口，不是增加两辆车的恢复保证。见[解释及独立复核](feasibility-method-v6.md)。

## 保守预测负结果

一日预测只将下一天预测容量降到与当前观察的较小值，不读取未来。它是保守假设，未经验证的预测器。相对执行锁方法没有新增完成，反而损失2个50箱案例；旧控制也下降。因此网页默认回放执行锁方法，保留预测及全部负例。保守子模型不可行只表示该策略未找到方案，不能证明原名义模型不可行或最优。

## 公开数据的作用和限制

本轮检查11条公开来源轨迹，保存44个原件、许可和取证文件。4个有明确许可的数据包包括Amazon真实历史路线附件、具有真实重量体积但重构时间窗的DeliveringData、真实散粮港口OCEL日志，以及以加州运输历史为基础生成的作者MIT许可客户。没有取得可直接实例化本模型全部字段的PNC箱级订单，也不声称网上不存在此类数据。

MIT许可研究实例含47个客户（33 Delivery、14 Pickup）、1个depot及48×48有向距离/时间矩阵。39项机械检查通过，11项业务语义仍未知：矩阵缺行标签、窗口不是放行时间、depot Arr=0不是开班时间，缺车辆容量及港口作业链。道路矩阵为ORS估计、逐字段原实测值保真未知。两矩阵各4条非对角零弧，1,116/1,128个无序点对不对称，原样保留。没有补造release或班次，业务求解和费用估计均0。MIT是许可而非学校背书；输入审核不能称真实PNC可行性或费用验证。见[调查](real-data-investigation-v6.md)及[输入审核](public-orders-audit-v6.md)。

已有光阳真实闸口留出继续仅支持停留预测组件，不合并到合成排程成绩。已有提还箱、预约和费用协同研究限制新颖性，本项目贡献是机制、执行承诺、预算覆盖及可检查证据的结合，不能声称算法首创。
