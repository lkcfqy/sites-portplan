# 本轮真实浏览器自动化验收

本轮使用云电脑已经安装的 Chromium 154.0.8037.57 和 Python Playwright，在真实浏览器页面上执行点击、输入、键盘、下载和 Worker 生命周期检查。没有使用假 DOM 代替浏览器，没有读取用户的本地浏览器或私人业务资料。

首轮 45 项、另列补充 4 项全部通过，原始记录分别位于 `artifacts/browser-v12-first/` 与 `artifacts/browser-v12-supplement-first/`。这两批实际检查的构建来自提交 `a5f67e4276b45fb4955ffdd32d67cd308647029e`，视口为 **1440×1000 和 390×1000**。随后针对新增状态展示及已审核 V13 结果的候选构建，完整重跑同一套 49 项并全部通过（`artifacts/browser-v12-final/`），不将重复检查累计成 98 项。精确候选静态字节清单及源码提交绑定在原始记录；之后新增的验收记录和传输包另做发布字节检查及线上真实浏览器抽查。当前可发布结论和完整性绑定以 [浏览器验收记录](../data/browser-acceptance-v13.json) 为准。

受控停滞与晚消息测试仅在验收浏览器的 localhost 请求层替换对应 Worker 响应，保留真实父页面计时器、点击操作和取消逻辑。它们检验异常处理，不是自然求解超时、新原生算法成绩或业务执行结果。其余正常教学步骤使用实际浏览器 GLPK 计算。

截图、逐项断言、事件、输入输出 JSON、下载 SHA 和执行时的静态文件清单均保留。证明归档保留下载收据、格式检查与原始字节 SHA，没有重复收录下载的 ZIP/PDF/PPT 二进制。PDF/PPT 的原始材料另在项目及发布包中保留；候选构建下载的中间源码 ZIP 仅保留下载收据，不能从截图证明归档还原其 ZIP 原始字节。最终完整源码由网站另列的全部源码分包提供，并独立检查其成员与 SHA。恢复证明归档使用 `scripts/restore-evidence-v12.py --manifest data/archives-v13/browser-first/manifest.json --destination data/evidence-v13`，恢复器的 V12 名称是共享的无损传输格式，不表示变更了 V12 原始研究。

这次完成的是自动化产品操作验收。本人参赛资格、报名、当届规则/AI 条款、实际个人复现和答辩仍须有真实记录，不能由自动化代签。V12 默认替换门槛失败和全部负面记录保持原样；V13 受控端点开发不属于新的正式留出实验。企业资料和联系人仍为可选增强项。
