# PortPlan v1 模型、费用口径与复现

本版是“公开标准费率 + 合成业务订单”的排程实验，不能称作实际节省或生产账单预测。问题边界：韩国 PNC 码头卸船、客户自行安排内陆运输、Maersk 普通干货进口箱；仅支持20/40英尺。不含冷藏、危险品、45英尺、inland carrier haulage、税费、特约免费期及运输价格。固定路线、每天一个时间桶；时窗、距离和卡车回程配对不建模。

## 公开来源及冲突

- PNC 2026正式标准费率 PDF 第3—4页：<https://www.pncport.com/resources/homepage/kor/data/2026_PNC_Standard_Tariff.pdf>。
- Maersk 韩国进口标准条款与费率：<https://www.maersk.com/local-information/asia-pacific/south-korea/import>。
- 费率以 PNC 正式2026 PDF 为本版标准。PNC 在线询价页仍出现8,800/17,600/30,800/44,000等不同价格，因此不能直接把本模型视为应付账单；合同与正式报价优先。
- Maersk表格按daily rate列出时段。当前实现**采用逐档累加解释**；没有取得韩国具体合同的账单算例交叉核验。这是显式假设，不是已核实的合同结论。
- 两项费用在本情景分别计算并相加。实际合同的适用性仍需核对，禁止重复计入已被合同包价覆盖的费用。

## 时间与收费

所有业务日按Asia/Seoul。输入卸船时刻必须带时区；系统先换算韩国时间。日历包括周末/节假日。

PNC：08:00前卸船，当天开始；08:00整或之后，次日开始。开始日至提箱gate-out日包含两端。前4天免费。总天数5—7、8—9、10—14、15及以上的费率依次为9,100、18,200、31,850、45,500韩元/TEU；**到达的最高档费率乘全部超过4天的天数**。40英尺取2 TEU。14→15天的20英尺例子：318,500→500,500韩元，相差182,000。

Maersk：卸船当天到空箱gate-in当天包含两端，10天免费。20英尺第11—15天每天15,000、第16—20天30,000、第21天起50,000；40英尺分别30,000、50,000、90,000。当前实现逐档累加。

`totalCost`为从卸船开始到提还箱事件的完整费用。`sunkCost`是代码兼容字段名，界面称“规划日前费用基数”：在计划开始前一天按相同费率计算的累计费用，不表示已支付或会计上已确认的沉没成本。`incrementalCost = totalCost − sunkCost`是本次比较目标。PNC新档重算历史天数所增加的费用被计入incrementalCost。常数对所有策略完全相同，因此最小化totalCost和incrementalCost给出同一个最优排程。

## 输入与约束

```json
{
  "id":"example", "horizonStart":"2026-10-12", "horizonDays":14,
  "truckCapacity":4, "warehouseCapacity":2, "stagingCapacity":8,
  "containers":[{
    "id":"CW-001", "sizeFt":20,
    "dischargeDateTime":"2026-10-01T07:00:00+09:00",
    "releaseDay":0, "unloadDays":1, "dueDay":8, "dataOrigin":"synthetic"
  }]
}
```

容量可以是一个非负整数，也可以是长度等于horizonDays的每日整数数组。每个箱占一个装卸槽和一个堆放槽，**不是TEU容量**；40英尺与20英尺在本版操作容量中相同，但费用不同。releaseDay、dueDay都是从horizonStart起0基索引。dueDay约束卸货最后一天，属于硬截止；无晚交罚金软化。每只箱须在计划末日内还空箱。

每箱选择三个整数日：提箱p、开始卸货u、还空箱r。持续卸货L天。

- p ≥ releaseDay；u ≥ p；r ≥ u + L。当天提箱可以当天开始卸货；最早在最后一个卸货日的次日还空箱。
- u + L − 1 ≤ dueDay。没有“迟到但记作满足”的情形。
- 每天提箱数量加还箱数量 ≤ truckCapacity。每个事件各消耗一个**运输移动额度**；不是卡车台数或完整来回趟数。
- 每天处于u ≤ d < u+L的箱数 ≤ warehouseCapacity。
- 每天处于p ≤ d < r的箱数 ≤ stagingCapacity，即提箱日至还箱前一天占场地。还箱日视为早间释放场地；没有日内时刻调度。

所有策略接收完全相同的订单、未来可用容量和硬截止。本版为全信息静态确定性问题，不能据此声称支持随机到港或实时控制。

## MILP

事件变量x(i,d)、y(i,d)、z(i,d)分别代表在第d天提箱、开始卸货和还空箱，都是0/1。每类事件每箱恰好一次。release、deadline和horizon提前裁掉不可用的日期。

顺序使用累计约束：截至d的卸货开始次数不超过截至d的提箱次数；截至d的还箱次数不超过截至d−L的卸货开始次数。运输/卸货/场地按上面的事件及累计事件求和约束。

目标为Σ费用(p) + Σ费用(r) − 期前常数。费用函数先在所有允许日期计算，作为线性目标系数；因此PNC阶梯回溯计费不需要错误地近似成普通线性费率。模型是整数线性优化，glpk.js 5.0.0 / GLPK求解，默认15秒、相对MIP gap=0。

- `optimal`：GLPK返回模型最优状态（未另行提供可由第三方检查的证明证书）；只针对所述模型及参数。
- `feasible`：有符合约束的解，但可能未证明最优。检查optimality是heuristic还是feasible_incumbent_only。
- `infeasible`：空日期域或GLPK证明无可行解。
- `time_limit`：预算内没有得到可行整数解，不是不可行证明。
- `no_feasible_schedule_found`：某个贪心策略没有排完所有箱，也不是不可行证明。

失败方案的费用为null，不能用部分排程费用参与节省率比较。API对每个成功结果再运行独立于MILP约束生成器的排程审计。依赖GLPK为GPL-3.0，分发必须保留相应许可和源码义务。

## 对照策略

三个可复现贪心基线均逐个选择箱，为所选箱保留最早可行的完整提—卸—还序列，检查相同容量及截止限制。没有可行剩余箱即报告失败；不会通过放松约束伪造可行结果。

1. FIFO：按卸船时刻先后，再按箱号。
2. earliestFreeEnd：先按两个费用体系中最早免费期结束日，再按dueDay、卸船时刻、箱号。在相同免费期、相同卸船截止时刻下，与FIFO可能相同，这不是独立强基线。
3. marginalCost：先按当前可取得的最早提箱日期；该日期相同时，按将提还箱事件各延后一天所增加的总费率成本降序，再按dueDay、卸船时刻、箱号。这个“延后一天”是费用风险指标，不声称该反事实本身满足容量。

基线都知道完整未来数据，但只有MILP进行全局重排搜索。因此结果能比较这些实现的策略，不足以证明胜过所有已有调度算法。评审应与**最佳可行基线**配对比较，并报告零改善、贪心失败和求解未证最优的场景；禁止只挑收益大的案例。

## 验证与复现

`node --test tests/engine.test.mjs`覆盖公开费率边界、08:00与时区、日期包含端点、不可行实例、相同seed重现、容量审计，以及小实例的**独立穷举oracle**。oracle独立枚举所有p/u/r组合、独立写费用和容量计算，比较最优totalCost，避免只测试求解器自身输出。

`makeDemoScenario(seed,count)`生成完全合成的订单。seed随机规则只是实验设计，没有声称拟合真实物流分布。公开港口作业时长等辅助数据不能替代实际PNC进口客户订单。下一版优先加入匿名订单回放/业务流程核验、准确日内时窗和合同参数、滚动到港/容量扰动评估、强启发式对照，再考虑把模拟收益用于任何实际价值声明。
