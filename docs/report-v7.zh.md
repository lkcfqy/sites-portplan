# PortPlan V7：在完整执行与费用之间继续改进

V7完成一轮预先固定的新种子实验，并增加公开资源排程原模型验证和真实港口事件原生关联审计。结果支持局部费用修整的实用价值，也显示它仍不是普遍优胜策略。比赛排名不能由这些实验推断。

## 方法与来源

费用修整使用与V6相同的完整构造种子，只在当前调用剩余预算内尝试单箱和双箱日期调整；每次接受须当前联合费用严格降低并通过执行锁、资源与费用审计。完整种子可保留，没有新的全局最优或不可行证明。某次局部修整不增费不意味着整条滚动路径或不同策略之间费用必然不增。111次已接受完整种子的前后日期由独立Python重新计价。

经典GRASP基准按Resende/Ribeiro的受限候选集、多起点与局部改进机制适配本模型；含项目自己的资源评分与锁约束，不是论文完整复现，不代表当前最强方法。公开代码和许可清单见[外部方法](external-methods-v7.md)及[适配说明](grasp-adaptation-v7.md)。

## 公开原模型验证

PSPLIB J30的480个公开生成实例保留原始作业持续时间、前置关系和4种可再生资源，比较串行生成与迭代生成排程；不填造提箱、还箱、费用或客户字段。原最优参考只用于评分，不送入算法。两方法均完成480例，达到参考值172→353，307例改善、173例持平、0例更差；总makespan31,179→28,604，减少2,575抽象时间单位（8.2588%）。迭代方法仍有127例未达到已知最优，最差差距12单位。

此处是预加载后的100ms合作式调用预算，下载、解析和参考值关联在计时之外，不能与港口滚动5秒冷进程成绩混用。迭代法全部用满256次迭代，中位耗时12.576ms，基线0.032ms；更好解不代表更省CPU。0负例部分来自只保留更好可行候选的机制；这不是最先进算法或真实费用收益证明。来源、原件SHA、可下载重跑和独立960结果/候选审计见[公开验证](public-validation-v7.md)及[独立资源审核](public-resource-review-v7.md)。原数字档仅按官方研究使用条款下载，不作为自有许可原件再次公开打包。

## 真实港口事件关联

Zenodo公开粮食港口OCEL SQLite保留原生对象关联：按货车对作业计划的赋值时间窗口关联事件，不从事件ID字符串猜订单。6989条typed事件出现记录对应6950个唯一事件ID，39个重复ID；事件对象关系也有39个完全重复。天真ID连接会得到7492行，不能当成7492个真实动作。

489条赋值窗口中454条入港→装货→满载称重→出港阶段完整且顺序一致，35条缺失；缺失阶段和41条异常事件保留。完整记录的入出港记录时钟跨度中位4231秒，装货记录到称重记录中位2108秒。时区、设备时钟同步、装货时间代表开始还是结束未知，因此这些不是服务时长、设备利用率或集装箱卸货参数。该数据为粮食港口，不是PNC集装箱订单，0次求解、0项费用收益推断。原件与全部窗口逐条SQL独立对照见[原生审计](port-ledger-v7.md)和[独立关联审核](port-ledger-review-v7.md)。

## 证据与复现

三份独立检查分别复核合成滚动、公开原模型排程、真实港口事件关联；它们是项目内部独立实现，不是第三方签章。正式首次结果原档不可覆盖，精确首次源码保存在vendor/experiments/下；新实验默认写artifacts。按README合并网站四个下载包，缺失118MB原档可由30个固定SHA无损分块恢复，不重新求解。网站浏览器投影仅减少内部求解调试信息，费用、日期、状态、执行、审计和全部方法/分母保留并无损压缩。
