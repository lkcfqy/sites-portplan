# PortPlan V9：真实业务试点输入与验收

这是一份尚未执行的试点安排，不是访谈、用户认可或企业收益证据。项目目前没有取得真实箱级订单、采购报价或财务逐票核对；不将准备材料写成业务验证已完成。

## 先取得能回答问题的一份小样本

建议先选一批已知普通干货进口箱和一个仓库资源池，例如10–30箱及一周左右作业记录。这只是便于核对的试点规模建议，不是代表性抽样或统计结论。先保留实际人工计划，再用同一份当时已知信息进行比较。

| 输入 | 必需信息 | 当前工具中的位置 |
|---|---|---|
| 箱级订单 | 箱号、20/40ft、带时区卸船时刻、可提日、连续卸货日数、卸货完成期限 | 工作台CSV/JSON导入；来源统一未核验 |
| 资源容量 | 每日运输箱次、卸货槽、在场箱/TEU、开始日与规划终点 | 情景JSON及operations |
| 已执行事实 | 实际提箱、开始卸货、还空日；当前决策日 | 资源补救fixedEvents与minEventDay；不能把未执行预约写成过去锁 |
| 有效报价菜单 | 资源、覆盖日、整包数量、整包KRW价、最早可用日、明确授权声明 | 资源补救actions；未知价格留空并停止该建议，不自行补造 |
| 人工基准 | 完整提卸还日期、当时信息、原两费及采用的合同 | 独立核对记录，不用算法自己的方案冒充人工计划 |
| 财务核对 | 实际合同免费期、档位解释、税费/运输费覆盖与真实账单 | 逐票核对表；标准公开价预测不自动当成实际发票金额 |

可以从工作台导出当前情景作为字段模板，但其中演示箱是合成数据，必须明确替换。`data/pilot-container-fields-v9.csv`仅含空字段头，不含真实订单；`data/pilot-action-menu-v9.json`是空菜单，不是报价。

## 一次可复查的试点步骤

1. 记录业务人员实际目标、人工基准和当日可见信息，再运行模型；未来实际冲击只用于事后评价，不提前交给规划器。
2. 先核对日期、单位、连续卸货、40ft的TEU、同日提还两次运输和过去锁。约束违规必须为零才讨论费用。
3. 分开列原两费、沉没费用、新增两费、额外采购费和合计；采购最小仅限所输入菜单，不能算菜单外资源或全部企业物流成本最优。
4. 给业务人员检查逐日建议、所需资源能否真实交付、日期变更是否可接受。未采纳、无解、超时、费用上升同样记录。
5. 事后使用实际执行与账单核对预测差异。没有实际执行或逐票核对时，只能报告计划预测及人员反馈。

## 记录与通过条件

| 项目 | 填写方式 | 当前状态 |
|---|---|---|
| 数据/报价/合同适用性 | 实际提供者、核对日期、字段或文件引用 | 未取得 |
| 人工计划与模型信息一致 | 明确同一订单、当日信息和资源范围 | 未确认 |
| 物理可行性 | 独立逐日资源、期限、过去锁审核，列所有违反项 | 真实数据尚未审核 |
| 费用与采购 | 原两费/新增两费/沉没/采购分别复算，保留原金额及不利差额 | 未进行财务核对 |
| 稳定性 | 改动了多少待执行日期，实际调派人员如何评价 | 未反馈 |
| 业务决定 | 实际采纳/拒绝、理由、后续实际执行 | 未进行 |

通过技术审核不替代业务采纳。费用没有下降也应如实记录；改期可能增加真实成本，目前没有把改期次数换算为实测工时或金额。访谈内容、采用承诺、签名和本人理解都必须来自真实发生的记录。

## 建议向实际计划人员核对的问题

- 当天最难协调的是车辆、连续卸货、在场空间，还是合同免费期？哪项信息能在早上确定？
- 增加一个资源包的价格覆盖哪些日、哪些动作，是否允许叠加，最早何时到位？
- 已执行动作、已确认预约和可以调整的计划如何区分？
- 一份两费更低但频繁改期的方案，实际是否更好？一次改动带来哪些可记录工作？
- 哪种无解或超时说明能帮助采取行动，哪些建议仍缺必要的业务条件？

这些是未来访谈提纲，尚未向任何企业或个人发送。
