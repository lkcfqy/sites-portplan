# PortPlan V1 — 强评审质询与补证实验

审阅日期：2026-10-12。范围：README、模型、来源审计、实验文档、来源登记和已保存的24场景结果；针对疑点抽查费用函数、基线、生成器、打包脚本及两份官方PDF。未进行企业访谈、现场验证或官方评审；本文件也不是官方评分、获奖概率或外部专家认证。P0表示影响当前对外结论可信度或可执行性的关键问题，P1表示下一轮证据与方法优先项。

交付修订说明：下文保留审查时发现的问题。V1 交付前已收窄费用基数、内部核验、模型内可行和求解器最优状态的措辞；界面同时显示增量与总收费口径，披露嵌套场景，并把所有上传记录标为未核验。求解器源码来源另见 `solver-source.md`。强基线、业务有效性及创新性问题仍然开放。

**判断：V1是具有可核验费用机制的、可运行的情景研究。9.81%的计算成立，但尚不能说明真实企业价值，也不足以证明方法优于强现有方法。当前最应加强的是对照强度、收费与作业假设的稳健性、可归因的贡献证据。** 不应因为加入更多真实但不相关的数据而提高实证定位。

## 已排除的两项错误指控

- **没有依据认定PNC仓储费与Maersk combined D&D必然重复计费。** `data/public/maersk_pnc_storage_2023.pdf`英文第2页明确说PNC与进口方之间的storage在Maersk自身D&D规则之外处理，并要求客户另遵循D&D标准或合同。`docs/source-audit.md`第2节据此把两项相加是有原始依据的研究设定。剩余问题是具体业务是否确实适用该服务组合、合同免费期与协议价，不是“combined”这个名称自动包含码头仓储费。
- **2026 PDF优先于旧价格网页有根据。** `data/public/pnc_2026_standard_tariff.pdf`明确2026-01-01生效，第4页给出15日20英尺箱`11×45,500=500,500`。本版最高档追溯所有收费日的函数与此一致。旧网页冲突已经披露；不能从此直接认定实现用错年度，也不能反过来宣称真实账单必然等于PDF标准价。

## P0：先解决的可信度与业务有效性问题

### 1. 收费确定性仍弱于“可验证费用函数”的直观印象

位置：`README.md`“核心方法”、`docs/model.md`“公开来源及冲突”、`data/source_registry.json`的`maersk_korea_import`及`tariffs.maersk_korea_import_combined_dry`。

Maersk逐档累加是明示实现解释，尚无本地合同账单算例。PNC标准价与真实结算适用性也未核实。数学代码可以正确执行假设，但不能通过自己的测试证明假设正确。强评审会问：“改变免费期或D&D解释，排序与9.81%还在吗？”

处理：当前维持“指定公开标准及解释下的费用”。实验1用合同参数与收费模式敏感性量化影响；未证实的替代模式必须标为压力测试，不能冒称另一种官方费率。真实业务适用性仍是证据缺口。

### 2. 方案满足抽象资源约束，不等于运输现场可执行

位置：`docs/model.md`“输入与约束”；`src/engine.js`的`scheduleUsage`；`src/solver-glpk.js`相应资源约束。

提箱可同日开始卸货，卸货结束后至少次日还箱；还箱日早间释放箱位；20/40英尺均占一个槽；两次运输各耗一个额度；不考虑路径、距离、司机工时、预约、日内卸船/通关、指定还空场站接收窗口。以上均是清楚披露的模型简化，**不是已查明的MILP约束错误**。但它们可以改变临界费率日的选择、箱位占用和可行性，尤其强制次日还空可能人为增加D&D。

所有箱在规划末日前清空也会产生末端效应；实际持续运营可能允许滚动遗留订单。当前“可执行排程”只能指模型内可行日计划。实验3应量化这些假设的影响，再决定哪些约束必须升级。

### 3. 9.81%是有效的窄比较，不能作为独立实证或企业预测

位置：`docs/evaluation.md`首轮结果、`data/benchmark.json.summary`、`src/engine.js:193`生成器。

独立从逐场景比较项加总，确认23对场景为46,607,450→42,033,900 KRW，差4,573,550，增量比例9.812916%；同批总收费99,671,300→95,097,750，比例4.588633%。排除一个无基准完整方案的场景并另报可行率是合理做法；逐场景取最便宜可行基线也较严格。没有发现本轮选取单一劣质基线或把部分订单费用纳入比较的证据。

但：只有4条伪随机流；每个seed的8箱数据恰是16箱前8箱，三种容量重复同一订单。因此24场景不是24个独立数据集。订单全部是规划前3—14日卸船的积压箱，75%左右立即可提，卸货仅1或2天，截止期与释放日按同一窄规则生成。结果不能描述正常新到港业务，也不宜给出把24场景当独立样本的置信区间。总额加权受大箱数、高费用和容量配置的人工混合权重影响；ample仅0.73%、tight为16.28%，不能只展示总数。

这里缺失的是外部有效性证据，而非百分比算术。公开光阳车辆进出与仁川闸口快照都没有进入优化输入；`docs/source-audit.md`对此披露正确。不得将“取得58,171条真实记录”紧挨“节省9.81%”排版而省略其未用于收益验证的关系。

## P1：强评审会继续追问的技术与贡献问题

### 4. 三个基线不代表三类强调度方法

位置：`src/engine.js:132–163`、`docs/model.md`“对照策略”。

三个方法共享“逐箱预留完整最早提—卸—还序列”的不可撤销构造，只改变优先级。`earliestFreeEnd`取两种免费期的较早结束日；在当前所有箱PNC免费4日、Maersk免费10日的设定中，总是PNC决定这个指标，因而主要重复到港年龄排序。24个场景中FIFO与该基线10个总成本完全相同（其中包含共同失败），差异也不能证明算法多样性。边际费用规则先按最早提箱日排序，再比较一天费用差；它不总是优先最大费用风险，也不看未来跨档跳涨。其局部不可撤销性会人为制造失败。

全信息对全信息是必要公平条件，却不足以证明方法竞争力。至少加入截止期/松弛度规则、允许重新插入与交换的局部搜索，以及在同等时间预算下搜索多个优先级的强基线。比较的不应只是不同排序名称。

### 5. 尚未隔离到底什么贡献产生收益

位置：`docs/source-audit.md`“比赛与竞品核验”、`docs/competition-brief.ko.md`“차별화 가설”。

公开费率查询、D&D提醒和通用MILP都不是新算法。已有资料只证明部分产品有收费/提醒功能，没有证明它们缺少联合优化，也没有系统检索学术文献。当前可主张的是“将明确的追溯阶梯费用、提卸还时序和资源约束放进可核验原型”，仍是应用贡献假说。

强评审会问：“收益来自正确收费规则、全局搜索、或故意紧张的合成容量？”需要消融实验：在同一真实收费函数下评价只优化仓储、只优化D&D、联合优化的排程；用误设为平滑/逐档的代理费用求排程后，再按真实基准复算。这种反事实用于说明费用机制的决策影响，不是建议业务使用错误收费。文献/产品对照应记录检索日期、检索式和公开可确认功能，把“未找到”与“没有”分开。

### 6. 可复现不等于第三方验证，最优状态也不是可移交证明文件

位置：`README.md`“可复现实验”；`docs/evaluation.md`标题及“独立检查”；`docs/model.md`对`optimal`的解释。

独立写的枚举/费用复算器有实际价值，但它仍是项目内部验证，不是独立机构验收。GLPK返回最优状态是模型内的算法结论；“最优证书状态”容易被理解为已经保存了可由另一程序检验的证明证书。应说“求解器返回最优状态”，需要更强声明时再保存模型、参数、求解日志及界/间隙。

`docs/evaluation.md:5`说协议在首次实验前写入，但现有交付文件没有足够的不可变版本记录供评审确认先后。这不是证实造假；应保留带时间/提交哈希的协议快照，或只称“固定实验协议”。90个排程复算、穷举小例子、来源规则核实和真实业务验证是四种不同证据，答辩中不能互相替代。

### 7. 软件许可与本人贡献证据还不完整

位置：`README.md`“许可”、`THIRD_PARTY.md`、`scripts/prepare-public.mjs:34`、`docs/competition-brief.ko.md`末段。

本地`node_modules/glpk.js/package.json`明确为GPL-3.0，项目采用GPL-3.0是方向正确；不能把glpk.js当MIT。源码ZIP排除了`node_modules`，目前含应用源码、锁文件及许可证，尚未展示与所分发GLPK WASM一一对应的依赖源码和构建链。`npm ci`能取预编译依赖，不等于已经证明可重建该二进制。这里是需补齐的分发证据，不能仅凭本次审阅断言法律违规。应固定上游版本/源码、GLPK来源和WASM构建说明，核查第三方通知后再称“完整对应源码已提供”。

公开网页可读取并不自动说明原站HTML/PDF可随GPL代码任意再分发；`source_registry.json`只有部分数据明确记载使用许可。第三方材料保持原权属声明正确，但仍宜逐项补许可证/转载依据或只分发必要摘录与原链接。

韩文摘要已披露使用AI辅助，仍需核实主办方单人资格及AI边界。不要编造已获批准。参赛者需要保留个人做出的假设选择、修正和验证记录，能独立解释费用断点、累计约束及失败案例；开源求解器与AI生成部分都不得冒称个人原创算法。

## 立即统一的文案

1. `docs/evaluation.md:14`的“规划期开始前已发生的费用常数”改为“按规划期前一日规则计算的费用基数”。`sunkCost`只是兼容字段名，不能作为已支付或会计上不可追回费用的证据。减常数不改变最优排程，但会改变节省百分比分母；总费用4.59%应与增量9.81%同时展示。
2. `README.md`“独立审核按原始输入重算费用”应指明是**基准实验审核器**。当前通用API的`auditSchedule`核验排程约束；`scripts/benchmark.mjs`才独立复算费用。不要暗示每次上传订单求解都已经过另一份收费实现。
3. “独立核验”注明“内部独立实现交叉检查”；“最优证书状态”改为“GLPK返回的模型最优状态”。“可执行”注明“在所述日级模型内”。
4. “首次运行前预先固定”和“完整源代码分发”的证据按上文补齐，否则收窄措辞。保留现有“合成结果、非企业节省、非首创、非夺冠预测”边界。

## 单人可做、仅需公开来源的三个最高价值实验

### 实验1：收费与合同参数稳健性矩阵

用已保存PNC 2026规则和Maersk公开表为默认值。预先固定PNC免费期、D&D免费期、费率缩放、收费组合适用/不适用以及D&D分档解释压力测试；每种取值标明“官方标准”“合同情景假设”或“未核实压力测试”。在相同订单/容量下重跑所有方法，并报告排程改变比例、费用差、可行率、跳档暴露及最坏损失；用一组模式生成的排程在另一组模式下复算，测量错误解释风险。验收不要求结果仍好看，而要求明确指出哪些结论稳健、哪些被费率假设决定。预计1—2天。

### 实验2：强基线与机制消融挑战赛

冻结当前24场景为开发集，另固定未使用种子为验证集；增加截止期/最小松弛度、最佳插入+交换局部搜索/多起点基线。给MILP和搜索同等墙钟预算并公开初始化计时口径。加入PNC-only、D&D-only、joint及代理费用消融，全部按同一真实研究基准费用复算。规模覆盖16/50/100箱，报告可行率、配对费用、求解间隙/状态、全分布与失败实例，不只给平均节省。允许强基线消除原收益；这本身能识别贡献。预计2—4天。

### 实验3：日级假设、末端效应与滚动扰动压力测试

固定三种生成机制：当前积压箱；规划期内分批到港；同一批集中释放。明确仍为合成，不能用光阳场内23分钟中位数冒充PNC公路运输或仓库卸货耗时。测试返空允许同日/必须次日、箱位按箱/按TEU、未来1—2天运输额度降低、卸货延长及不同规划长度。滚动实验每次只给当时已知信息，离线全信息最优只作不可实施的参考下界；全部方法使用相同实际扰动。报告原计划执行后的违约/超容量、修复成本及重新求解次数。验收输出应能说明哪些运营假设最值得优先向业务方核实。预计2—3天。

这三个实验不需要伪装真实订单，也不依赖获得私人账号或企业数据。它们能把下一版从“有数字的原型”推进到“知道何时有效、何时失败的研究”；真实应用价值与竞赛资格仍需要各自的直接证据。
