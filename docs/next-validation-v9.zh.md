## 已有证据决定优先级

V9 首次正式实验覆盖 144 个业务场景、每场景 3 次算法/时钟重复、5 方法，共 2,160 个冷启动 episode。两个面板分别含 72 个业务场景和每方法 216 次 episode；重复不是新的独立业务样本。

| 方法 | 同分布完成 /216 | 压力完成 /216 |
| --- | ---: | ---: |
| 稳定保留 V5 | 129 | 72 |
| V7 | 150 | 85 |
| V8 | 96 | 57 |
| V9 | 150 | 84 |
| 原生 HiGHS | 156 | 119 |

及时候选 gate 已补齐，V9 相对同场景 V8 的完成情况明显改善；这仍不代表整体算法领先。V9 与 V7 在同分布的完成情况相同，在压力面板有 1 次完成增益、2 次完成损失。V9 对 V7 的共同完成配对中：

- 同分布新增两费节省为 **−1.219%**，95% 场景聚类区间 **[−2.622%, 0.389%]**，分母为 50 个场景、150 个配对 episode。
- 压力新增两费节省为 **0.049%**，区间 **[−0.053%, 0.239%]**，分母为 28 个场景、83 个配对 episode。

两个区间都包含零，不能宣称 V9 已建立稳定费用优势。原生 HiGHS 的完成与费用值得继续研究，但仍有 V7 能完成而它未完成的情况，且共同完成配对中的改期明显更多。不同方法对的分母不同，不能据此制作跨分母的综合排名。

显式资源菜单补救及研究界面已实现；菜单内采购最小的证明不等于已经取得真实资源、实单采用或真实财务节省。浏览器完整操作和参赛者本人答辩仍需实际验收；企业业务反馈只在自愿增加该可选证据时单独核验。

## P0：解释压力面板的两次 V9 完成损失

**当前进展：**V10已完成相关原档逐例诊断和相同前缀离线复核，见[诊断证据](v9-loss-diagnosis.zh.md)。下面保留最初任务与门槛作为检查依据，不再整体标为“尚未执行”；后续仍不能把离线可行解当成已恢复完整未知未来路径。

优先检查这两项已保存原档：

1. `v9-stress-new-arrivals-tight-n50-r4::repeat-3`
2. `v9-stress-batch-release-tight-n50-r1::repeat-2`

**任务与产物：**制作逐例诊断表，绑定输入、冻结实现、V7/V9 episode 和对应 SHA。定位第一处分歧日，列出当日公开容量、过去锁、上一计划、候选日期、gate 拒绝/接纳时刻和失败原因。区分以下解释：初始方案导致路径不同、保留方案失效、构造未及时形成有效候选、最终审核/选择未及时接纳、当前观察加既有执行前缀不可行，以及真实未来轨迹已经无法完成。缺少证据时保留“尚未确定”，不能把没有及时 incumbent 写成资源数学无解。

若需要离线重放，只在复制的开发诊断目录进行，固定原始执行前缀，比较同一个当前公开快照；额外求解预算及全知未来仅作为标明的离线诊断。保留首次结果，不把诊断重放替换正式成绩。完整路径的两个算法可能有不同初始决策，不能把费用或完成差异自动归因为恢复能力。

**验收门槛：**

- 两次损失都能定位到具体决策日及可核对的原始证据；不能只给一个汇总的“超时”标签。
- 每项提出的原因都有能排除至少一个替代解释的检查，产物注明诊断预算和信息范围。
- 若修复代码，先增加能复现该机制的定向边界用例，并检查及时候选、过期候选、错误费用、过去锁和最终选择的接纳规则。
- 任何尚未解释的损失明确保留，未完成根因确认时不标记此项通过。

## P1：研究原生求解与计划稳定性的 Pareto 取舍

**当前进展：**V10的同费保留方法、首次新实验和共同集合分析已完成，见[结果报告](report-v10.zh.md)。但压力面板仍损失原生对照已完成的3次执行，默认替换门槛未过。下述规则继续约束下一版研究，不能用已看过的V9/V10输入代替新验证。

目标是检验：能否保留原生求解的可行性与两费表现，同时减少待执行日期变化。没有实测的改期工时或合同成本时，不把一次改期任意折算成 KRW，也不将费用与改期加权成一个自定“综合分”。

**任务与产物：**

- 保留原生 HiGHS、V7、V9、稳定保留为明确对照。若开发原生稳定性方案，先说明是费用优先的词典序优化，还是在预声明费用界限内减少改期；固定日期仍严格不可改。
- 若分两阶段求解，200 ms 是两阶段及审核合计的日调用预算，不能每阶段各用 200 ms。原生启动仍计入共同 5 秒冷启动 episode。
- 分开展示全部场景上的及时完成率，以及明确共同完成集合上的新增两费、总两费和改期。共同完成集合、配对数及条件选择偏差必须展示；未完成费用保持 null。
- 用 Pareto 表或图列出不可同时改善的取舍。为多方法比较预声明共同集合与配对分析规则，不跨不同分母宣布某方法“综合最优”。
- 把最差费用损失、完成损失和改期增加的案例与平均结果一起展示。

**验收门槛：**所有方案物理/历史/费用审核违规为零，方法及分析规则冻结后再进入新验证。若要推广为默认方案，须事先声明完成不退步、费用及稳定性的选择规则；不能等看到新结果后换主要指标。若完成、费用或改期仍互有得失，交付物应明确适用条件和选择，而非宣称全面胜出。只有在预声明共同完成样本上，费用区间支持正节省时，才可称该条件费用指标存在优势；它仍不代表全部路径收益。

## 任何新方法都需重新划分开发与验证

V9 首次结果已经看过。V8 与 V9 旧场景今后都属于可用于分析的开发/回归资料，不再称为下一版的新留出。正式记录与冻结源码继续保留。

先用开发资料完成方法、参数、测试、日时限和分析方案。然后预先声明新的业务种子、面板、重复、失败规则、比较对象和成功门槛，冻结协议字节及完整源代码，再首次生成并执行新的验证输入。保持首次 append-only 结果及独立物理/费用/bootstrap 复核。不得挑选成功种子、删除昂贵或无解场景、只保留表现最好的一次重复，也不得用更长日预算的离线诊断替代原在线成绩。

总体完成率目标应结合明确的资源不可行性边界制定，不能承诺在任意冲击下都完成。只有当前观察与执行前缀内的严格证明，才可以解释相应层次的无解；全知离线证明不能冒充在线算法的先验信息。

| 操作链 | 通过条件 |
| --- | --- |
| 进入工作台、滚动模拟、资源补救和研究页 | 页面可达，导航与返回正确，当前方法及数据来源清楚 |

| 滚动成功、失效和超时 | 展示当日已知信息及执行锁；不把失败当成已完成；超时或未知费用为 null |

| 资源菜单补救 | 两种目标标签准确；未授权/过去/未到可用期的整包排除；无解、可行、已证明最小与未知状态区分 |

验收记录需写浏览器、视口、发布提交或版本、步骤、结果和未解决问题。通过条件是上述关键路径全部通过、没有会改变完成/费用/授权含义的未解决问题。截图或浏览器记录必须来自实际操作，不用生成图片代替。浏览器端 GLPK 与原生 Python HiGHS 的运行位置继续明确区分。

## 可选增强：企业小批量试点

此项不是公开路线、研发或竞赛准备的前置任务，当前未执行不视为阻塞。仅当用户主动提供有权使用的企业记录或明确改变路线时，才按[旧版业务验证说明](pilot-validation-v9.zh.md)增加这类证据。旧说明中的必做口径由[当前约定](../AGENTS.md)更新，不要求另外寻找联系人、计划人员、合同或报价。

若自愿开展，可使用一个资源池的小批量记录，保存当时人工计划和信息后进行同输入模型预测。旧设计的10–30箱只是便于逐票核对的可选规模，不代表总体抽样充分或当前必需任务。

**仅用于可选企业结论的输入：**带时区卸船时刻、20/40ft、可提日、连续卸货日数、期限、每日资源与箱/TEU单位、已执行事实、适用合同，以及有来源、有效期、整包覆盖日、价格、授权和最早可用日的报价。没有真实报价时不能把演示价用作业务成本证据。没有日内约束及路线资料时，保留每日原子模型的适用限制；不影响已有公开研究按原范围继续。

**验收门槛：**

- 所有必需字段有来源并经实际提供者核对；重复、缺失、时区或单位冲突已解决。未执行预约不能被写成过去锁。
- 保留模型运行前的人工基准与当时信息，使用相同订单、资源及评价范围；未来实际事件只作事后评价。
- 对每箱逐日检查资源、连续卸货、期限及过去锁，违规为零后才比较费用。
- 分开复核原两费、沉没费用、新增两费、采购费和范围外成本。与合同/账单逐项一致，或提供逐项可解释差额；未解释误差不计入节省。
- 真实计划人员逐项记录接受/拒绝及理由，采购资源是否能交付、改期工作量是否可承受。拒绝、无解、超时和费用上升全部保留。
- 未实际执行时只报告预测与人员反馈；完成真实执行和逐票财务核对后，才报告对应批次的实际结果。

若实际开展，才交付去标识输入核对、人工计划对比、真实反馈和费用差异说明。数据、报价和反馈须来自实际记录，不能由AI代写成“已认可”。本计划不要求取得业务联系人，不自动对外发送消息或购买资源；尚未开展时不声称企业认可或实际节省。

## P1：参赛者本人复现与答辩

已生成的 PDF、PPTX 和报告只是材料。本人理解与现场演示能力须由参赛者实际完成并留下记录。

**复现任务：**从下载归档恢复冻结版本，核对 SHA，按复现说明运行手写小情景及独立审核；能指出当前发布展示与首次冻结实现的区别。完整正式实验若重新运行，必须另开目录并披露时钟重复差异，不覆盖首次成绩。

**答辩验收：**本人不用代答即可解释以下问题，并现场完成一条成功及一条失败演示：

1. 为什么 2,160 次 episode 只对应 144 个业务场景，三次重复如何进入区间？
2. V8 退步的原因是什么，V9 修复了什么，为什么仍不能宣称超越 V7？
3. 两费、沉没费用、新增费用、采购价各是什么，哪些成本尚未进入模型？
4. 每天规划器知道什么，为什么不能看到未公告的恢复时间？
5. 连续卸货、TEU、同日两次运输和过去锁如何限制方案？
6. 菜单内采购最小证明需要什么条件，为什么不等于资源实际买到或最少动作？
7. 原生 HiGHS 的优势、完成损失、改期代价与浏览器运行差异是什么？
8. 共同完成条件费用和置信区间有哪些局限，真实收益需要什么证据？

按最新官方时长和材料要求实练；尚未核实的规则明确列为待确认，不自行编造评分权重、允许的 AI 使用方式或提交要求。通过条件是核心事实无误、能够自主操作和复现、面对负结果能如实解释，且关键问题均能独立回答。本人可以用录屏和日志记录实际演练日期、问题及改进；有自愿观察者时可增加反馈，但不以专家或联系人为前提，不由AI宣称本人已经通过。
