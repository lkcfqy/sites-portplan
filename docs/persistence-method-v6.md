# V6：保守的一日容量预测

这是另一个可被推翻的策略假设，不是新算法首创或未来扰动持续期的已知事实。它与 V6 执行锁恢复策略使用相同构造、审计和剩余预算 MILP，只改变传入的未来容量预测。

在当前决策日 d，历史及当天容量不变；d+1 的每种资源预测取 `min(原预测容量, 今天已观察容量)`，其余未来日期沿用原预测。本轮固定一日，不在看过新种子成绩后调整天数。订单仍全部已知，核心因果协调器继续屏蔽尚未揭示的事件和私有持续期。

降低预测容量可能给出更早完成、较少暴露的日期，也可能让原本可行的名义未来在保守模型中无解、提高费用或降低完成率。因此保守模型的 `infeasible` 被对外映射为 `no_feasible_schedule_found`，保留 `forecastSubproblemStatus`，不证明原观察模型不可行；最优结果也只称可行，不能把保守子模型最优冒充名义模型最优。

每次调用的合作预算从 wrapper 进入开始计，包含预测、选项克隆与底层恢复计算；预测和克隆消耗从传给底层的剩余预算扣除。GLPK 内部装载和原生停止检查仍可能超过合作截止点，因此记录真实墙钟，正式比较另由父进程执行整个冷 episode 的共同硬限时。

API 为 `createPersistencePlanner({persistenceDays:1,timeBudgetMs:200,...})`，`persistenceForecast(s,options,days)` 只读取调用者提供的情景和当前日。长期故障或不同冲击机制不在一日假设下获得稳健保证。字段声明、全部新旧对照分母及完整负结果以 [protocol-v6.json](../data/protocol-v6.json) 和首次 `rolling-v6.json` 为准。

下载复现采用三个 ZIP：源码与历史证据、新 V6 实验数据、新公开取证原件。均以 `portplan/` 为根，解压到同一个父目录可合并为完整工作区；没有删除失败数据或许可证。
