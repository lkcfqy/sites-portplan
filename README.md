## Build and run

Use Node.js 22.12+ (or a compatible supported version), npm and Python 3 (standard library only for export packaging). No runtime API keys or environment variables are required by this browser-only application.

```sh
npm ci
npm run dev
# Production assets and local preview:
npm run build
npm run preview
```

The export's `build` and `dev` use the new `scripts/prepare-public-export.mjs`: it prepares only retained evidence/static assets, without attempting to restore missing multi-GB historical archives. The original full build remains available as `npm run build:full-evidence` **only after separately restoring all required original evidence**. No solver or experimental outcome has been modified by this adapter.

Larger retained JSON results are stored losslessly as `.json.gz`; the adapter serves the same decompressed bytes (except explicitly documented deployment-identity redactions) at the appropriate existing app paths. Before running research scripts that expect source `.json` files, run `npm run data:restore`. `npm test` includes historical evidence/recovery tests that require excluded inputs; a full suite pass is not claimed for this slim export.

## Scope and missing resources

`PUBLIC_EXPORT_OMISSIONS.json` is the exact excluded-file list, compression list and identity-redaction list. Excluded: Git history; node_modules/build outputs; frozen historical `.bin` bundles and nonessential raw public-data downloads/databases. Current V6/V7 browser views were regenerated with the original scripts and verified against frozen checks; their losslessly compressed original result JSON, all linked generated PDF/PPT material, historical source/test snapshots, and upstream solver source archives are retained. The build generates six real sanitized source/evidence download packages and replaces the current package manifests with their actual sizes and hashes. These are current export packages, **not the original historical download packages**. Raw public input collections remain incomplete where listed in the omission manifest; no claim of full original-Site byte parity or complete research reproduction is made.

Public-data source URLs, hashes and licenses remain in `data/source_registry.json`, `data/public/**` metadata, research scripts and `THIRD_PARTY.md`. Use those exact recorded sources / acquisition scripts to obtain needed original public inputs; do not replace frozen evidence with rerun results. Dependency source provenance and upstream locations remain documented in `docs/solver-source.md`; the original upstream solver source archives and their metadata are preserved under `vendor/source/`, including the original published npm package; its existing license notices are retained.

Actual Sites project/repository identifiers and owner-specific URLs have been replaced with placeholders. `.openai/hosting.json` is **a configuration example, not a deployable identity**; configure your own Site before deployment. No credentials, user conversations, account records or database exports are included. No deployment or external service connection occurs during the export preparation.

## 核心方法

- PNC：2026正式公示普通进口干货箱费率；4个日历日免费，超期按最终达到的最高档位追溯计算。卸船当地时间08:00之前从当日起，否则次日起；包含提箱日。
- Maersk：韩国标准进口干货箱Combined D&D，按日历日自卸船日至还空箱日（均包含），以累进档位计算；合同适用性和累进解释作为披露假设，不代表账单确认。
- 混合整数线性规划（MILP）：每箱选择提箱日、卸货起始日、还空日。卸货可跨多日；交付期限为硬约束；规划期内必须还箱。
- 每次提箱和还箱各占一次运输作业。运输容量不等于车辆数量。20/40英尺箱各占一个抽象箱位。
- 基准：FIFO、免费期最早结束、边际费用、截止期优先，以及固定次数的多起点排列搜索与插入/交换。强基准不是文献最先进方法；其固定候选次数与MILP时间上限不等同CPU预算。所有方法使用相同输入和硬约束。
- 目标只包括码头仓储费与船公司D&D。排除运价、税、仓库租金、特殊箱、临时封控和合同议价。

V2费率/作业参数、强基准及推荐机制见 [docs/model-v2.md](docs/model-v2.md)；原始公式见 [docs/model.md](docs/model.md)。改变免费日也会平移档位，这是研究假设，不能冒充延长免费期的真实合同。

## V2 固定实验与反例

主实验协议在运行前提交为 `1fb4678f2e3f4179b638b19938c42249c455cd59`。48个不同种子、16/50箱、三种生成机制和两级容量全部保留；另外4个100箱控制与56个敏感性/消融配置单独报告。输入均为合成，结果不是企业实测收益。

| 结果 | 本轮证据 |
|---|---|
| MILP完整可行 | 44/48：33个模型最优，11个未证最优；另4个模型不可行 |
| 多起点+局部搜索完整可行 | 36/48 |
| 可配对费用比较 | 36个场景，新增两费下降15.74%，总两费下降8.86% |
| 没有费用优势的情形 | 14个新到港可配对场景，两方均为零费用 |
| 100箱反例 | 1个新到港场景强基准0费可行，MILP在2秒内无可行解；因此产品保留并推荐可行候选，不掩盖求解器失败 |

这些百分比是对人工场景组合的总額加权描述；12个没有可行基准的场景不虚构费用。单个方法的失败与数学模型不可行严格区分，全部原始状态及运行时间保留。强基准是增强的内部实现，不是已复现的文献最先进算法。

见 [V2实验报告](docs/evaluation-v2.md)、[V2原始记录](data/benchmark-v2.json)、[冻结协议](data/protocol-v2.json)。V1的24个相关场景和9.81%原始结果仍保存在 [V1报告](docs/evaluation.md)，不与V2合并成一次实验。

## 静态最优与抗扰动的代价

固定6个额外基础情景、4种作业假设、3类扰动。原静态计划在18次指定扰动中16次失效。事后重算18次可行，但知道全部未来扰动的重算不等于在线恢复。

看到这些失败后，另行冻结了**探索性保守策略**：所有箱卸货预留1天，全部日期运输预留2箱次。6个保守计划在18个指定扰动中均保持可行；代价为总两费增加4,652,550 KRW（32.29%），规划期新增两费增加76.88%。这是指定不确定范围内的成本与可行性取舍，不能外推随机失效率或现实服务保证。

见 [压力测试](docs/robustness-v2.md)、[保守缓冲实验](docs/conservative-v2.md)。该V2历史模型当时未包含已执行动作冻结、道路路线、预约窗口和实时信息到达，不能称完整在线调度；V4以后加入已知订单、未知未来容量下的执行锁，仍无道路路线和新增订单。

## 输入格式

推荐先从界面导出模板。箱记录CSV列：

```csv
id,sizeFt,dischargeDateTime,releaseDay,unloadDays,dueDay,dataOrigin
CW-001,20,2026-10-01T07:00:00+09:00,0,1,8,synthetic
```

日期时区必须显式给出，显示和计费统一使用Asia/Seoul。`releaseDay`、`dueDay`均从规划开始日计0起；`dueDay`为卸货完成的最晚日。真实用途还需要确认可提箱时间、海关放行、提单、运输及还箱预约等字段。用户提供的数据标签不构成真实性认证。
